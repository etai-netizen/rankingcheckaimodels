Ranking methodology

This repo measures generic topic search ranking — not branded queries. Each probe simulates what a practitioner would see if they asked a category question with no brand names in Cursor agents, Google Web, or Google Gemini.

Probe flow (this repo):

  • Load the entity ranking-check prompt from prompts/entities/*-ranking-check.md (shown in each column below).
  • Run one primary + one secondary generic query from that prompt — e.g. governance, edge AI, or green hydrogen topics from config/target-repos.json.
  • For each agent, record the top 5 competitor domains cited and where the target site would rank.
  • Append results to meta/rankings-history.json with brand, platform, model, tier, and competitors.
  • If tier, competitors, or losing queries changed vs meta/agent-prompts-used.json, update the entity prompt and rebuild this dashboard.

Agents assessed per entity: Composer 2.5, GPT-5.5 High, Fable 5 High, Google Web, Google Gemini. Cursor uses three Cloud Agent models (9 automations at 06:00 GMT = 3 entities × 3 models). Each model is logged separately so agent charts compare models.

Tier assignment (lower = better ranking):

TierMeaning
1Target site is the first source cited
2Target site appears in the top 3 sources
3Target site is mentioned but competitors dominate
4Target site is rarely cited (regulators, vendors, Wikipedia lead)
5Target site does not appear in agent answers

Decision filter (every probe): Would the target site appear in the top 3 sources when a practitioner runs this generic topic query in Cursor agents or Gemini?

Chart calculation: Trend graphs plot the average tier per entity or per agent model for each day, month, or year from probe history. Entity panels show the latest tier per agent. North star: move each brand toward tier 1–2 on generic topic search over time.

Excluded: Branded queries, site: searches, SEO rank trackers without an agent citation check, or content quality scored in isolation.
